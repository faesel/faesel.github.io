15:T297c,<h2>It started with curiosity, now I can&#39;t live without it</h2>
<p>A few months back I wrote about building <a href="https://www.faesel.com/blog/gridwatch-copilot-session-manager">GridWatch</a> — a desktop dashboard for GitHub Copilot CLI sessions. At the time it was a fairly simple tool: browse your sessions, check token usage, see an activity heatmap, and transfer context between sessions. Handy, but admittedly a bit bare-bones.</p>
<p>Well, things have changed. Quite a lot, actually!</p>
<p>I use Copilot CLI every single day. It&#39;s become my default way of working — planning, coding, reviewing, researching. Because I use it so much, GridWatch has evolved alongside it. Almost every new feature exists because I personally hit a wall and thought &quot;I really wish I could see this&quot; or &quot;why can&#39;t I manage that from here?&quot; It&#39;s the beauty of building tools for yourself — you never run out of ideas, just time.</p>
<p>Version 0.28.0 is what I&#39;d call the &quot;actually feature-complete&quot; release. Let me walk you through what&#39;s new.</p>
<p><img src="//images.ctfassets.net/wjg1udsw901v/7LaR3wTfm4gfRA3GUSi1ZE/7cee576a37700503c5c9d03d11898f69/Screenshot_2026-04-12_at_10.33.34.png" alt="Gridwatch homepage"></p>
<p>Oh.. and I also updated the logo with a cool neon retro vibe,</p>
<p><img src="//images.ctfassets.net/wjg1udsw901v/5aiFHwcSUxySEJqXdbuUcI/4577e4577806d51ceccfc228afdef4b4/Screenshot_2026-04-12_at_10.57.01.png" alt="Gridwatch Logo"></p>
<h2>Skills Management — Your Copilot Playbook</h2>
<p>One of the biggest additions is a full skills management panel. If you&#39;ve been using Copilot CLI skills (those <code>SKILL.md</code> files tucked away in <code>~/.copilot/skills/</code>), you&#39;ll know that managing them means bouncing between your file explorer and a text editor. Not exactly elegant.</p>
<p>GridWatch now lets you browse, create, edit, duplicate, and delete skills right from the dashboard. You can toggle them on and off, tag them for easy filtering, import from files or folders, and even export them as zip archives. The rendered markdown preview also gives you a readable view of the skill.</p>
<p>There&#39;s also an estimated token usage indicator for each skill, which has been surprisingly useful. When you&#39;re working within a finite context window, knowing that one of your skills is chewing through a big chunk of it before you&#39;ve even typed a prompt is valuable information. I&#39;ve used this to trim down some of my more verbose skills — cutting out redundant instructions, tightening up examples, and generally making them leaner. It&#39;s one of those features that quietly makes everything else work better.</p>
<p><img src="//images.ctfassets.net/wjg1udsw901v/7i0K4bhEgvJwZwq95kRl5z/182823a5a623809b71cd2a02c17f7a0b/Screenshot_2026-04-12_at_10.37.26.png" alt="Token usage for skills"></p>
<p>Overall the skills pane is kind of feature that sounds small on paper but saves you a surprising amount of context-switching throughout the day.</p>
<p><img src="//images.ctfassets.net/wjg1udsw901v/1gL3skRq2k5VU4fGTYkHYv/0d7ca9ef2aea3cea5ebafe396a4b8e61/Screenshot_2026-04-12_at_10.35.37.png" alt="Skills panel"></p>
<h2>MCP Server Dashboard — Taming the Context Window</h2>
<p>This one&#39;s for anyone who&#39;s installed a few too many MCP servers and wondered why their context window is filling up before they&#39;ve even started working.</p>
<p>The MCP dashboard gives you a complete view of all your installed Model Context Protocol servers — both local stdio and remote HTTP. You can enable and disable them on the fly, which is genuinely useful for managing context window bloat. Each server&#39;s full tool catalogue is displayed, grouped by category with descriptions and parameter schemas. GridWatch actually queries each server live via JSON-RPC <code>tools/list</code> to pull this information.</p>
<p>You also get to see environment variables (with secrets properly masked, don&#39;t worry), connection times, and command details. It&#39;s essentially a control panel for your entire MCP setup.</p>
<p><img src="//images.ctfassets.net/wjg1udsw901v/33vFXB3RbzYL547csFH5hm/5fb66fef281c35eb52dc848b530d2a45/Screenshot_2026-04-12_at_11.15.05.png" alt="MCP dashboard"></p>
<h2>Agents Panel — Know Your Crew</h2>
<p>Copilot CLI has built-in agents — Research, Code Review, and Coding — and if you&#39;ve been writing custom agents, those live in <code>~/.copilot/agents/</code>. GridWatch now surfaces all of them in a dedicated panel.</p>
<p>You can see session counts and usage stats per agent, with linked session history so you can trace exactly which sessions used which agent. Custom agents get an orange CUSTOM badge to distinguish them from the built-in ones, and there&#39;s a rendered markdown viewer for reading agent profiles.</p>
<p>I find this especially useful for understanding which of my custom agents are actually pulling their weight and which ones are just... sitting there. We&#39;ve all got that one agent we were really excited about for a week.</p>
<p><img src="//images.ctfassets.net/wjg1udsw901v/WlUW2NMo3cI37eK43o9ZJ/98139af6010e20325c3a5a3d5d7fffa3/Screenshot_2026-04-12_at_10.42.49.png" alt="Agents dashboard"></p>
<h2>Session Type Detection — Research vs Review vs Code</h2>
<p>GridWatch now automatically identifies what kind of session you&#39;re looking at. Research sessions get a RESEARCH badge, code review sessions get a purple REVIEW badge (detected by spotting Copilot&#39;s <code>code-review</code> agent usage), and everything else falls under coding.</p>
<p>Combined with the search and multi-select tag filtering that was already there, it makes finding that one session from last Tuesday where you researched that obscure API issue significantly less painful.</p>
<h2>Compaction Tracking — Where&#39;d My Context Go?</h2>
<p>Ever been deep into a Copilot session and noticed it suddenly &quot;forgot&quot; something you told it earlier? That&#39;s compaction — Copilot compresses the conversation context when you&#39;re approaching the limit. It&#39;s necessary, but it can be disorienting.</p>
<p>GridWatch now detects when compaction happens and shows you the trigger utilisation, how many messages were replaced, tokens saved, and the compacted summary. There&#39;s even an expandable checkpoint viewer so you can read the full checkpoint markdown inline. No more guessing about what Copilot decided to keep and what it threw away.</p>
<p>They say an elephant never forgets. Copilot, on the other hand, occasionally needs a spring clean — at least now you can see exactly what got tidied up.</p>
<p><img src="//images.ctfassets.net/wjg1udsw901v/63GmJ9XAI29q9TAu9W1pws/9402f5f869a4b093a36213bc8dd0e95d/Screenshot_2026-04-12_at_11.44.49.png" alt="compaction-tracking"></p>
<h2>Performance — Lightning Fast (No, Really)</h2>
<p>I&#39;ll be honest, earlier versions of GridWatch were... let&#39;s say &quot;enthusiastic&quot; about loading data. When you&#39;ve got hundreds of sessions, eagerly parsing every single one on startup isn&#39;t exactly snappy.</p>
<p>Recent releases have included significant performance upgrades. Session lists are now paginated at 20 per page, agent session lists default to the 5 most recent with a &quot;show all&quot; toggle, and MCP tool discovery results are cached locally. The result is a dashboard that feels genuinely responsive, even with a large session history.</p>
<p>Behind the scenes I&#39;ve also introduced memoization in each tab to stop re-redners of the screen.</p>
<p>The days of staring at a loading spinner while GridWatch parsed your entire Copilot history are firmly behind us.</p>
<h2>Security — Because Best Practices Matter</h2>
<p>Security has been a first-class concern throughout the recent updates. The renderer process is fully sandboxed with context isolation — it communicates with the main process only through a typed <code>gridwatchAPI</code> bridge, with no generic IPC exposed. A strict Content Security Policy is applied in production (no inline scripts), and all IPC handlers validate session IDs as UUIDs with path traversal protection.</p>
<p>Your GitHub PAT (if you use one for AI Insights ... totally optional) is encrypted at rest via Electron&#39;s <code>safeStorage</code>, which means macOS Keychain on Mac and DPAPI on Windows. The <code>shell.openExternal</code> call is limited to HTTP(S) URLs only, and macOS builds use hardened runtime for notarisation compatibility.</p>
<p>In short — your data stays local, your secrets stay encrypted, and GridWatch doesn&#39;t cut corners.</p>
<h2>Other Quality-of-Life Improvements</h2>
<p>A few more things that didn&#39;t fit neatly into the sections above but are worth mentioning:</p>
<ul>
<li><strong>Typeahead tag management</strong> — tagging sessions and skills now features a typeahead search, so you can quickly find existing tags or create new ones without remembering exact names. It sounds minor, but when you&#39;ve got dozens of tags across hundreds of sessions, the friction adds up fast.</li>
<li><strong>Copilot instructions context cost</strong> — the session detail view now shows you the cost of your copilot instructions in terms of context window usage. If your <code>.github/copilot-instructions.md</code> is eating up a significant chunk of the window before the conversation even starts, you&#39;ll know about it.</li>
<li><strong>Token utilisation at init and peak</strong> — every session now displays both the initial token utilisation (what the context window looks like when the session first spins up) and the peak utilisation (the highest it reached during the session). This gives you a much clearer picture of how your sessions are consuming context — and whether your instructions, skills, and MCP servers are leaving enough room for actual work.</li>
</ul>
<h2>Try It Out</h2>
<p>GridWatch is free, open source, and runs entirely on your machine. You can download the latest release from <a href="https://github.com/faesel/gridwatch/releases">GitHub</a> — there are installers for both macOS (arm64 and x64) and Windows. Ive now tested on both platforms and all works great!</p>
<p>Ive built this tool for myself and others, there are no analytics or outward calls (except to check for new updated versions of Gridwatch).</p>
<p>If you use Copilot CLI regularly, I genuinely think you&#39;ll find it useful. And if you&#39;ve got feature ideas or feedback, the <a href="https://github.com/faesel/gridwatch">repo</a> is open for issues and contributions.</p>
